# 独立预览与菜单性能阶段（2026-10-30）

## 结论与边界

已在 `worktrees/pulse58-integrated-fixes/pulse` 当前集成版 1.0.58 实现并构建。长混合文字/彩色表情日志的整数像素滚动测试，完整帧耗时中位从 **352.5162ms 降至 16.6813ms**。包含帧末提交与呈现，不是只测一个函数。

这是一项速度与内存之间的取舍：该样本打开时私有常驻增加约 **1.87MiB**，关闭后立即增加约 **0.97MiB**。不宣称本轮降低闲置内存，也没有测长期闲置。精细触控板、小数像素位移及导航动画变换继续使用原生路径，不宣称这些位置已获得同等提速。没有做真实鼠标长时间交互验收，也没有与 File Pilot 做本轮对照。

## 实现

- 正文首次仍用原生 DirectWrite 绘制。上一帧正文绘制超过 8ms、长度在 4096～32768 个 UTF-16 单元之间，才记录原生绘制命令。短文件和超过此长度的源码视图不创建这份缓存。
- 记录完整原始布局、绘制原点及彩色字体命令，不拆分文字重新排版。选择、查找、行号仍分别绘制。
- 只有相对录制原点的平移严格为整数物理像素时复用；分数偏移保留原生像素吸附，不反复录制缓存。125%文字尺度的正常滚轮位移也在对照范围内。
- 布局、主题、字号、设备、绘制参数变化时失效；切换文件和关闭预览释放持有的命令、设备与参数引用。没有清空共享图形缓存或强制压缩工作集。
- 菜单主面板、子菜单、提示框与独立预览复用帧内高对比度状态快照；帧外仍读取系统设置。

主要代码：`src/ui/quick_preview_text_draw.cpp`、`quick_preview_window.cpp/.h`、`quick_preview_chrome.cpp`、`fluent_menu.cpp`。定向入口：`src/bench/quick_preview_audit_test.cpp`、`src/bench/menu_frame_test.cpp`。

## 无截图开销的最终测量

同一个 SELFTEST 程序，在独立桌面与独立配置目录中运行；向真实预览窗口注入约32700字符的固定正文，避免读用户文件。混合文字三组、英文两组交替新旧顺序，各进程三轮、每轮12帧；每轮取帧中位，再对轮次中位取中位。每次包含正文→表格→短文件→超限文本→关闭→销毁，全部10进程退出码0。开始时没有编译进程；开始时编译进程列表、程序哈希及日志均保留。

关闭截图路径，避免PNG和反复尺寸变化的资源进入日常内存数据。私有常驻按 QueryWorkingSet 非共享页统计；不是提交内存，也不是包含共享页的总工作集。这里的关闭数据是关闭后立即采样，不等于长期闲置。

| 指标 | 原行为 | 新策略 |
|---|---:|---:|
| 混合文字/表情日志整帧中位 ms | 352.5162 | 16.6813 |
| 混合文字/表情日志打开时私有常驻 MiB | 21.051 | 22.918 |
| 混合文字/表情日志关闭后立即私有常驻 MiB | 22.453 | 23.422 |
| 纯英文日志整帧中位 ms | 16.6770 | 16.6716 |
| 纯英文日志打开时私有常驻 MiB | 16.035 | 17.965 |
| 纯英文日志关闭后立即私有常驻 MiB | 21.863 | 21.975 |

纯英文整帧仍约16.7ms，不能称为帧率提高；实际正文CPU样本约3.1ms降至0.2～0.3ms，英文样本也触发了缓存。8ms是上一帧成本的启发式门槛，不能保证所有稳态较快文件都不缓存。

混合文字首次正文渲染三次中位554.1517→527.3346ms，英文两次61.9609→50.8667ms；样本少且波动，**不宣称稳定首开提速**。这也不是应用启动或包含文件读取、解码的端到端打开时间。首次保留原生路径，后续有一次缓存准备成本。补测一组：混合日志原生第二/第三帧463.93/436.85ms，新策略准备帧692.46ms、随后9.01ms；英文对应10.36/17.04ms与11.39/15.02ms。这是单组补充证据，不能当作稳定上限。**混合日志的一次性准备帧仍有明显停顿，是尚未解决的限制**；不能只用稳态16.7ms声称所有交互都无卡顿。原始记录在 `preparation_final/`，四进程退出码0。

关闭后的剩余常驻差异没有进一步定位来源。缓存拥有的引用释放检查已通过，但不能据此声称进程内存完全回到原水平。

证据：`bench_data/preview_menu_frame_20261030/normal_final/summary.json` 及各进程日志。入口：`pulse.exe --quick-preview-frame-perf`，仅测试构建支持；设置 `PULSE_TEST_DATA_DIR` 和 `PULSE_TEST_PREVIEW_NO_CAPTURE=1`，基线另设 `PULSE_TEST_TEXT_BASELINE=1`，英文另设 `PULSE_TEST_PREVIEW_ASCII=1`。不要用发布程序承担测试配置隔离。

## 排除、失败与修正记录

- 约32700字符的布局入口重复比较500次约1.4ms，而原正文绘制约331ms。因此没有为几微秒的比较增加身份管理复杂度。
- 初版立即录制带来首帧与内存额外开销，已改为先原生显示、再按成本启用缓存。
- `command_cache/`、`final/` 的最初预览截图是黑帧，相关像素一致结论全部作废。原始文件保留。修正为保存呈现前的HeldFrame，并增加非空白检查。
- `corrected_capture/` 的有效正文图暴露了小数滚动像素吸附差异；已通过完整原点与整数平移限制修正，最终有效图位于 `pixel_alignment_visual/`。
- 菜单初次探针缺少字体初始化、提示框未进入绘制，该轮失败保留，修正后再计量。
- 构建期间其他任务修改共享头文件，造成重复增量编译；一次正式构建对象文件拒绝访问，随后重试成功。测试变量与Windows small宏冲突已修正。没有终止其他任务、改动权限或删减测试来取得通过。
