# 通用第三方文件对话框接入：重新划定交付路线

日期：2026-10-30。此文更新第三方部分的后续路线；系统入口重构及独立 Win+E 策略保持原范围。

## 结论与责任

应按系统接口实现通用兼容层，不按应用名称不断增加特殊分支。当前 R24 是受控启动的有限能力验证包，尚不是日常软件的通用替换版本。此前过早让用户反复尝试不同软件，不能用大量自有测试通过掩盖真实覆盖不足。

可以统一覆盖使用相同标准接口的软件，但不能承诺所有软件的任意选择界面。公开 Windows API 文档分别定义 COM Common Item Dialog、传统 Common Dialog 和 WinRT picker，并未提供注册一个第三方 UI 即替换所有这些接口及应用自绘界面的统一扩展点。进程接入本身也需要独立实现。

## 本次实际证据

- R24 记事本：用户确认打开、另存为正常；此前选择和取消测试已记录。
- R24 Word：用户确认打开、另存为仍为系统原生，本轮失败。
- Word 会话 `{94D6B7EE-3157-4F9F-8062-ECBD132E9D06}` 记录两次 CoCreateInstanceEx 的 activation-adapter-entered / adapter-return，UI provider 加载返回 0；没有相应 wrapper setter、Show 或 Pulse 显示证据。不能据此说已成功替换对象，也不能认定某个具体 setter 是本轮原因。
- 同一日志还记录 child-startup-contract-native。该子进程是否承载本次对话框尚未证实，不能直接归因。
- 源码中 SetDefaultFolder、AddPlace、SetClientGuid、ClearClientData 仍明确回退；SaveProperties、SaveAsItem 等也未通用支持。即使修好 Word 的创建路径，基础契约缺口仍存在。

## 通用架构与实施顺序

1. **接入与诊断闭环**：COM 创建入口记录请求接口、上下文、线程模型、包装结果及具体回退原因；关联同一对话框对象的配置、Show、结果。覆盖已实现的创建与子进程路径，区别“未接入”“无法包装”“能力不支持”“显示失败”。先查清 Word 当前缺口，不增加 WINWORD.EXE 专用判断。
2. **公共对话框模型**：以 API 语义建模默认目录/显式目录、应用历史、常用位置、过滤器、文件名、扩展名、多选、结果与取消；统一事件和自定义控件状态。应用使用这些能力时直接映射到 Pulse，不因常见设置就整体回退。保持文件校验、覆盖确认及事件拒绝的真实语义，不能把未知选项直接忽略。
3. **标准接口适配**：COM 与传统 GetOpenFileName/GetSaveFileName 的 W/A 接口共享模型和 Pulse UI，分别负责调用约定、缓冲区与错误语义。已有传统接口显式适配测试不等于实际进程入口拦截已交付。WinRT / 系统代理选择器独立评估，不伪装为同一 COM 入口即可覆盖。
4. **日常启动接入**：处理普通快捷方式、文件关联、单实例转交、子进程和已有进程；补齐 x86/x64 对应发布组件、停用与升级。受控启动成功不能替代这一阶段。
5. **代表应用验收**：覆盖不同接口家族和调用模式后，才由用户做体验验收。应用测试是验证共性实现，不是每个应用各做一套。失败首先归到接口能力或启动机制；个别私有/自绘界面明确单列。

## 从当前代码出发的剩余成本估算

以下是单名熟悉 Windows C++ 的工程师的初步有效人日预算，不是两天内完成承诺，也不是已完成工作统计；完成第一项后按能力清单重新估算。按顺序计，不假设代理并行就等比例缩短。

| 工作包 | 初步人日 | 交付依据 |
| --- | ---: | --- |
| 接入诊断闭环、能力盘点、查清当前 Word 路径 | 2–4 | 每次回退可定位到对象和阶段，复现进入自动夹具 |
| 常用 COM 语义及 Pulse UI 能力补齐 | 10–18 | 按方法/选项/调用顺序与原生对照，不以软件名单作为分支条件 |
| 传统 W/A 实际接入与共同模型贯通 | 4–7 | 实际宿主入口、缓冲区/编码/取消返回一致 |
| 日常启动生命周期、位数、升级停用 | 6–10 | 不依赖测试专用启动页面；明确已有进程策略 |
| 代表应用综合验证、相关回归和打包 | 5–8 | 无静默原生回退、无重复窗口、结果可被应用正确使用 |
| **首个常用桌面标准接口版本合计** | **27–47** | 不包含下述独立探索项 |

WinRT/代理选择器先安排 3–5 人日可行性研究，再决定实现成本；不把研究预算当成实现承诺。任意应用自绘界面、跨用户/会话、完整可编辑 Shell 元数据和受保护进程不在上述范围。日常应用也可能使用这些不同入口，必须报告实测覆盖率，当前没有依据承诺“覆盖绝大多数”。

维护代价：系统和应用更新后需重测接入与返回契约；注入组件崩溃可能影响宿主，因此必须保留独立停用及可解释回退。发生回退的案例应记录为不支持/失败，不能因宿主仍可用就计为接管成功。

## 验收纪律

- 不再以“某个软件弹出一次 Pulse”作为通用阶段完成。
- 不放宽返回值、忽略配置或去掉验证来换取 Pulse 强行出现。
- 先用通用调用夹具覆盖已发现缺口，再做本机代表应用测试；用户负责最后体验确认，不承担重复诊断循环。
- 原有 R24 成功证据保留，Word 失败如实保留；本轮仅做日志/源码审查及路线文档调整，没有新增功能通过声明。
