# 批量删除性能优化（2026-10-29）

基于 `pulse58-integrated-fixes/pulse` 的 1.0.58 工作树。未打包。

## 改动

- 回收删除成功后复用已有 50 ms 进度通知限频。此前普通回收未命中 native `handled` 分支，每个文件都调用即时通知；小批次仍沿用原有逐项更新，权限交互及任务结束仍即时更新。
- 删除直接使用当前权限尝试，省去每项提前打开源文件和父目录的重复权限探测。只有权限失败且确认没有修改时才进入原有提权路径，保留重试、跳过和取消。
- 完成列表按选择数量预留容量。
- 权限回归扩展到永久删除和回收删除两种操作。
- 修正定向测试在新工作树缺少 bench_data 父目录时未能创建数据的问题；新增检查确认实际创建并删除全部 400 个测试文件，防止不存在的文件产生虚假通过。

## 实际验证

- 受影响程序及测试目标构建成功，没有新增编译警告。
- `pulse_authorization_flow_test`：22 PASS，包含两种删除的权限拒绝、跳过、取消及独立测试目录恢复清理。
- `pulse_elevated_delete_test`：16 PASS。
- `pulse_ops_test --delete-progress-only`：18 PASS / 0 FAIL；400 个真实文件全部删除，115 ms。
- `pulse_ops_test --recycle-audit`：27 PASS / 0 FAIL；含精确版本恢复、同名保留、缺失父目录、长路径及隔离回收数据清理。
- 本次三个源码文件差异空白检查通过。

第一次进度测试缺少真实数据，结果作废；第一次回收审计 9 FAIL 定位为测试目录创建失败。修复测试数据准备后重跑，以上仅计入有效结果。

## 测量说明

基准为 `pulse_ops_bench`，计时从 OpsManager 提交到任务完成，界面通知由独立模拟线程消费；不含真实窗口绘制及删除前确认。使用独立临时目录，回收数据按原路径准确恢复，不清空用户回收站。耗时数据不能外推到机械硬盘或网络位置。

初次旧版基线：1000 个小文件回收 4.466 s / 993 次通知；2000 个文件永久删除 0.603 s，2000 项目录树永久删除 0.522 s。该轮回收的产品撤销已恢复 785 项，终止基准专属进程后按唯一测试路径精确恢复剩余 215 项并清理对应索引，确认 1000 项齐全后删除测试目录；不计为完整批次产品撤销通过。

通知次数减少约 75%～90%，不再随文件数量逐项触发。删除耗时波动明显：新版第 3 轮运行到约 9 秒时报告 199/200，同期读取本机文件的短命令也出现超过 10 秒的等待。**现有数据不能证明删除吞吐稳定提高，也不据此推断慢的根因。** 本轮已确认的结果是去掉重复权限预检和大幅减少界面通知，不能报告固定提速倍数。该基准不包含真实窗口绘制，尚未量化真实界面响应改善。

旧版 3 轮、新版前 2 轮各原生 Undo 恢复 200/200。新版末轮原生恢复 199 项；确认专属基准和子 Shell 已停止后，按唯一测试路径精确读取回收索引恢复剩余 1 项，确认 200 项齐全后清理，不计为该轮完整原生 Undo 通过。

三个唯一测试根目录均确认不存在，对应回收索引及 payload 无残留；没有清空回收站或触碰其它文件。

以上四组有效定向测试合计 83 PASS / 0 FAIL。新版主程序：`build/pulse.exe`。未生成安装包或免安装包。
