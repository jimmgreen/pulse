# 批量重命名输入显示路径排查

## 现象与证据

用户反馈：同一测试版在一台机器正常，另一台 Windows 10.0.26300.9457、175% 缩放、自动文字模式下，批量重命名输入字符和光标都不可见，但预览随输入更新；地址栏和搜索框正常。

`app_hosted_edit.cpp::CreateHostedEdit` 无条件设置 `LWA_ALPHA=255`，使用 Windows 重定向表面；`BatchRenameWindow::CreateField` 原先仅在自绘不可用时设置，正常自绘走 `UpdateLayeredWindow`。共享输入代码主动隐藏系统光标，并把文字和自绘光标放入同一表面。主界面此前已经因上传位图被合成表面遮挡改用重定向路径（历史提交 `f101997`、`df19ee5`），批量重命名遗漏了这一处理。

故障机提供的旧诊断全部通过，只证明生成文字像素和上传调用成功，不能证明最终屏幕合成可见。它不能排除上述问题，也不能证明是 Windows 版本或缩放导致。

## 修改

- 批量重命名四个输入框与地址栏一致，无条件初始化 Windows 重定向表面，继续使用共享文字、选择和输入逻辑。
- 首次显示、移动或尺寸变化后提交文字；位置和尺寸不变时不额外绘制所有输入框。
- 定向检查同时记录直接上传和重定向绘制，断言真实批量重命名窗口的全部输入框采用与地址栏相同的路径。

## 实际验证与边界

本机隔离桌面运行真实批量重命名对话框，模拟 175% 布局，覆盖三种文字模式及浅深主题。旧实现新增的显示路径断言失败 24 次；修改后 127 项通过、0 失败，包括四个控件的表面类型、中文文本像素、WM_CHAR 追加、数值输入显示与编辑、文字高度边界。不执行重命名、不修改用户配置。

日志保留在主工作目录 `bench_data/quicklook-b/batch-surface-before.log` 和 `batch-surface-after.log`。

这些检查验证实现与呈现调用，不是故障机的最终屏幕观察。尚需用户在原故障机器验证修正版的字符和光标可见性；在此之前不能宣称该机器的故障已完全解决。

## 后续确认与共享控件修复

用户确认批量重命名修正版显示正常，但打开对话框仍存在同样问题。此前仅修改批量重命名不完整：各窗口虽然复用 `CreateChildEdit`，仍各自决定显示方式。

已将不透明重定向表面的初始化下沉到 `CreateChildEdit`；初始化失败时销毁控件并返回空句柄，避免返回显示方式错误的半成品。移除主界面、全局搜索、打开对话框、高级搜索、批量重命名、颜色输入、预览内搜索和菜单筛选八个使用方的重复设置。共享后端的模式切换和故障回退保留。扫描生产代码，原生 EDIT 创建均通过该入口；自测中的专用原生 EDIT 不在此范围。

本机实际验证：

- `pulse_child_edit_test`：239 项通过，包含共享创建默认表面、输入、选择、撤销、模式切换及失败回退。保留原有直接上传路径的低层测试，测试中显式切换，未删除旧覆盖。
- `pulse_file_picker_dialog_test --input-surfaces`：隔离桌面运行真实打开对话框，地址、文件名和搜索三个输入框的默认表面及中文输入共 7 项通过；取消退出，不选择或改动用户文件。
- `pulse_batch_rename_present_test`：127 项通过，确认移除局部设置后仍自动继承共享修复。
- 主程序及上述三个目标构建成功；改动差异检查通过。

日志分别为 `shared-edit-fix.log`、`picker-shared-edit-fix.log`、`batch-shared-edit-fix.log`，位于上述同一日志目录。其他使用方完成代码接入和构建验证，未逐一实测最终屏幕显示；打开对话框在原故障机上的显示还需新版实测确认。

## 纠正测试包中的旧版打开对话框

用户发现测试包显示的是已弃用的独立绘制版本。核对证实隔离分支漏合主工作目录尚未提交的新版，之前对旧窗口的输入验证不能代表新版界面验证。

现已合入主工作目录的打开对话框、标题/页脚、模型、加载器、文件操作适配，以及主渲染器的嵌入模式和调用方列表偏好传递。保留共享输入控件初始化。主工作目录未修改；对话框主体与其源文件相比只有共享创建入口和测试截图接口两处适配。

原独立窗口测试改为最终 `pulse.exe --picker-dialog-test --input-surfaces` 内执行，以使用同一套主渲染器；旧交互用例源码保留，通过 `--interaction` 可选择，未在本次宣称通过。画廊和布局测试同步到新版标题/页脚模型。

本轮实际验证：新版标题/页脚布局 186 项、加载与选择模型 60 项、最终程序输入与文件选择 9 项、复制/移动/重命名和 Shell 队列隔离 19 项均通过。`restored-picker.png` 已人工查看，确认主界面样式的侧边栏、地址栏、列表，以及无标签栏、无重复路径标题。截图不包含子窗口输入位图，文字最终屏幕显示仍以上一轮用户确认和控件测试为依据。

主界面 `--shot` 导出为黑图，不能作为普通主窗口的视觉验证通过；未据此扩大修改截图系统。相关日志以 `restored-picker-` 开头。新测试包为 `PulseSetup-1.0.53-current-picker-input-fix-test.exe`，此前的两个输入修复测试包含旧版对话框，已被此包替代。
