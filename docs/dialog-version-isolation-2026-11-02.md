# 对话框组件版本隔离

## 安装布局

主程序仍安装在根目录。第三方程序加载的对话框组件及其完整运行依赖位于 `DialogBridge/<manifest SHA256>/`，其中包含独立的 `pulse.exe`。目录名由清单原始字节的 SHA256 决定，不使用产品版本号作为唯一身份。

根目录 `dialog-current.json` 只包含 schema、directory、manifest_sha256。默认配置每次重新解析该入口，不把解析结果持久化为手动选择。用户明确选择的实验组件路径仍单独保存。

## 升级与失败恢复

先验证、刷新并发布完整的新组件目录，再用现有安装事务替换主程序、上一版本记录和当前入口，最后迁移属于本安装的已启用注册。默认未启用的功能不因升级而被启用；不覆盖其他安装的注册。

已加载 A 的宿主继续使用 A；升级后的新宿主使用 B。不尝试强制卸载宿主中的 DLL，也不终止第三方程序。

不可变组件目录不纳入根文件回滚：即使 B 已被新宿主加载，安装失败仍可恢复 A 的入口、主程序和注册。遗留的 B 等待安全清理，不能因其占用使回滚失败。

## 清理与边界

正常升级保留当前版本和上一版本。更早版本只在完整验证、身份复核、确认可删除后清理；遇到占用、未知文件或重解析点则保留。清理有数量上限，不以清理完成作为升级成功的条件。

卸载先恢复本安装的对话框注册。无法安全删除的组件保留并显示提示，不能声称已删除或保证重启后删除。

首次从旧平铺安装迁移时，已有宿主仍可能占用旧根目录文件，因而需要退出一次。新结构不能解除旧进程已经建立的锁。运行中的宿主不会立即获得新版代码，退出并重新启动后才切到新版。

## 定向验证入口

- `pulse_dialog_bundle_test --installed-pointer`：入口解析、资源隔离及恶意/损坏入口。
- `pulse_dialog_management_controller_test --installed-default`：默认配置不固定某个构建；测试程序需位于隔离安装根。
- `pulse_dialog_management_controller_test --auto-bundle <bundle>`：手动选择与自动注册状态。
- `pulse_setup_dialog_migration_test`：迁移事务、外部注册变更、恢复边界。
- `pulse_setup_dialog_versions_test --suite <A> <B> <C>`：真实外部文件锁、重复安装、失败回滚、中断恢复和旧版本清理。
- `scripts/test_dialog_version_upgrade.py`：真实宿主保持存活，连续升级 A→B→C，分别验证旧宿主重复打开和新宿主打开实际对话框。

测试使用独立目录及测试注册适配器，不改本机用户的真实注册和安装目录。真实 UI 宿主探针验证的是组件加载、窗口及生命周期，不等同于所有第三方软件的兼容性认证。
