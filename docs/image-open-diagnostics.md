# Pulse 图片双击无反应：诊断包

适用于：在 Pulse 的**文件列表“详细信息”视图**下，双击图片没有反应，但右键“打开方式”选择画图可以打开。

## 故障用户怎么做

1. 把整个压缩包解压到一个可写文件夹，例如“下载”。不要只在压缩包预览里执行。
2. 使用同一张图片，先在 Pulse 的“详细信息”列表中双击一次；记录时间和现象。
3. 再右键“打开方式”选择画图（选择“仅一次”，不要改“始终使用”），确认是否能打开。若方便，也切换为“大图标”视图双击一次，确认是否只有详细信息视图失败。
4. 双击 **`开始诊断.cmd`**，选择这张图片，按提示选择实际现象。脚本不会打开或读取图片内容。
5. 程序会在包内 `Reports\日期时间\` 下生成 **`report.json`** 和 **`summary.txt`**。把这两个文件、复现时间和 Pulse 版本发给开发者即可，无需发原始图片。

采集前可先关闭无关的重复 Pulse 测试实例，但不要为了排查强制终止正在执行文件操作的程序。

## 采集内容与边界

- Windows 构建号、PowerShell 位数；图片扩展名、路径长度、是否包含空格/非 ASCII 字符、文件属性和大小。
- 同一扩展名的 UserChoice ProgID、32/64 位注册表视图、默认动作、`open` / `edit` 命令、DDE / DelegateExecute 注册信息，以及只读关联查询的 HRESULT。
- 画图与照片应用的当前用户包版本/状态、画图系统可执行文件版本。
- Pulse 进程版本、可执行文件 SHA-256、位数与是否提升权限（若系统允许只读查询）。
- 最近 30 分钟内 Pulse **数值型**双击/打开链路日志，以及与图片应用相关的 Windows 激活/崩溃事件。

**不改注册表、不改默认应用、不修改应用权限、不请求管理员权限、不安装软件、不请求外部服务或上传数据、不启动图片查看器、不读取图片内容或窗口标题。** 除报告输出外，不修改用户文件。报告不保存所选图片的完整路径；账户路径、SID 和邮件地址会做基础脱敏。包注册命令、日志信息仍请在发送前自行检查。选择网络盘图片时，系统获取文件属性或使用文件选择对话框可能访问该用户选择的网络路径。

入口批处理中的 `-ExecutionPolicy Bypass` 仅用于本次 PowerShell 进程执行本地诊断脚本，不改变系统执行策略。若组织策略阻止脚本，不要擅自绕过组织策略或关闭安全软件，直接回传提示。

## 命令行用法（可选）

```powershell
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\Diagnose-PulseImageOpen.ps1 `
  -ImagePath "C:\某文件夹\出现问题的图片.png" -NonInteractive
```

不指定图片也可以仅采集某个扩展名：

```powershell
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\Diagnose-PulseImageOpen.ps1 `
  -Extension .jpg -NonInteractive
```

可选参数：`-Minutes 10` 缩短日志时间窗口，`-OutputDirectory "C:\可写目录\报告"` 指定报告目录，`-DataRoot "其他用户数据目录\Pulse"` 指定实际 Pulse 数据目录。企业策略下无权读取 Windows 事件日志时，报告会保留警告，也可用 `-SkipEventLogs` 只采集其余信息。

## 开发者判读

必须对照**故障电脑、同一图片、同一 Pulse 进程和复现时间**。开发者健康电脑上的信息、单个注册表差异或“没有日志”，都不足以确定故障用户根因。

新版打开日志链路：

`file_double_click → shell_open_queued → shell_open_begin → shell_open_result`

- `row_hit=0`：先看命中/布局/双击位置，不应直接归因于画图。
- 文件行命中，但没有默认打开入队：检查选择模型和打开命令是否提前返回。
- 已入队但无 `begin`：检查打开工作线程或已有队列阻塞。
- 有 `begin`、尚无 `result`：可能仍在文件夹检查或 Shell 交接中；先结合耗时和权限/网络路径判断，不重复触发大量打开。
- `result.error != 0`：按实际 Win32 错误码继续定位。例如 `2/3` 文件或路径不存在，`5` 访问拒绝，`1155` 无有效关联，`1156` DDE 交接失败，`1223` 用户取消。
- `error=0` 只表示 Shell 接受启动，**不代表画图已经显示了图片**；继续看包状态、权限差异及 Windows 激活事件。委派/打包应用的 `process_id=0` 可以是正常现象。

旧版本没有新增的打开事件很正常，不能据此认定双击没有发生。即使包状态或注册表看似正常，也不能替代故障用户的实测结果。
