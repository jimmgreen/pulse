# 临时 WARP 首帧与硬件设备交接：设计评估

状态：**尚未实现**。本轮只审查与记录设计；没有读取或启用
`PULSE_TEST_FAST_GRAPHICS`，没有改变默认图形路径，也没有加入临时迁移代码。

## 目标与现有证据

候选实验仅在环境变量 `PULSE_TEST_FAST_GRAPHICS=1` 时启用：硬件设备仍按现有方式
后台创建；若它尚未就绪，使用临时 WARP 显示完整首帧，随后迁移至硬件。
不写用户配置，不改变 Logo、字体、功能或默认设备选择。

已有独立设备实验报告 WARP 创建约 12–20ms、硬件约 177–407ms，但稳定帧
WARP 约 11–14ms、硬件约 1.6–5.6ms，且像素有约 1.2% 差异。这些是候选方案
的依据，**不是本方案已实现后的效果**。本项目细分启动 trace 测得硬件实际创建
179.92 / 190.94ms，工作线程启动延迟约 0.10ms，交接延迟 0.03 / 0.53ms。
因此真正待解决的是驱动初始化，不是线程排队。

## 为什么不能用现有 Recover 直接切换

1. `src/ui/ui_compositor.cpp` 的 `Compositor::Recover()` 先 `Shutdown()` 再 `Init()`。
   `Shutdown()` 会 `compositionTarget_->SetRoot(nullptr)` 并提交，然后释放原 swap chain。
   这是故障恢复，不是保留旧画面的交接；新设备初始化失败时也无法继续显示旧资源。
2. 同文件的 `t_shared_graphics` 是线程级单一裸指针，`SharedGraphics::users` 计数共享
   使用者。若 Quick Look、操作窗或其他主窗口仍持有 WARP，主窗口 `Recover()` 会
   继续复用它；直接替换全局指针则使旧设备使用者的计数/释放关系失效。
3. `DevicePrefetch` 只有 `started/done/device`。`CreateD3DDevice()` 在硬件失败时会
   自动回退 WARP，所以非空预取结果不代表硬件就绪。不能把它当成迁移目的设备。
4. `src/ui/render_caches.h` 明确依赖同一 UI 线程共享一个 D2D 设备。
   `src/ui/thumbnail_cache.cpp::SetDeviceContext()` 在设备变化时清掉 GPU 位图。
   若 WARP 窗口与硬件窗口交替绘制，共用缓存会反复失效，不能按普通上下文切换处理。
5. `src/ui/ui_renderer.cpp::SetCompositor()` 失效 SVG、图标、材质、文字等资源，但它
   并不提供“旧 renderer 继续显示、新 renderer 后台准备、失败回滚”的事务边界。
   `src/ui/ui_hover_preview.cpp` 的视频帧位图也有设备关联；异步缩略图返回和活动预览
   必须参与世代检查。
6. `src/ui/quick_preview_window.cpp` 与 `src/ui/file_operation_dialog.cpp` 各自处理
   `NeedsRecovery()/Recover()`。只修改主窗口无法协调这些共享设备使用者。
   `Compositor::FrameSourceUnder()`、`held_` 与 `frameCopy_` 还要求跨窗口画面资源兼容。

因此，仅增加环境变量、创建 WARP、硬件就绪后 `NotifyDeviceLost()` 的有限补丁不满足
无空白帧、可靠回滚、共享资源生命周期三个要求。本轮不提交这种实现。

## 必要的两阶段交接

### 1. 准备阶段：旧帧仍然有效

- 在 `ui_compositor.h/.cpp` 引入有明确所有权的设备世代：包含 D3D/DXGI/D2D 设备、
  backend 类型、generation，以及实际使用者引用。每个 Compositor 持有自己世代的
  强引用；默认世代引用与使用者引用分开，不能继续靠单个全局裸指针计数。
- 预取结果显式区分硬件成功、WARP 回退、失败。提供非阻塞查询/领取接口；UI 线程
  不等待驱动。后台线程只发布设备结果，不捕获 AppState、renderer 或窗口指针。
- 若进入 Compositor 初始化时硬件已成功，直接用硬件，不建立临时 WARP。
  若 WARP 初始化失败，保留原硬件等待/故障路径，不能让窗口处于半初始化状态。
- 硬件就绪后，在 UI 线程安全帧边界准备候选设备上下文、目标、文字、材质和 renderer
  资源。不能在 `BeginDraw/EndDraw` 中途、重入绘制或模态调用栈中切换。
- 旧 swap chain、composition root 与最后一个完整帧持续有效。不能先调用现有
  `Shutdown()`。候选构建失败只销毁候选，旧 WARP 继续工作，禁止忙循环重试。
- RenderCaches 必须按设备世代隔离 GPU 资源，或实现全部共享使用者协调迁移；CPU
  解码结果可以复用。异步返回不能把旧世代位图装入新世代缓存。

### 2. 提交阶段：新完整帧成功后才退休旧资源

- 使用最新 view model 在候选硬件资源上画出完整帧，强制全量重绘，成功完成 EndDraw
  和 Present 后才进入提交。不要以“设备已创建”代替“新窗口画面已就绪”。
- 需要专门设计 DirectComposition root/content 交接，保证旧画面一直覆盖窗口，直到
  新帧可以显示。当前 `CreateSwapChain()` 为 HWND 创建单独 composition target；
  不能假设对同一 HWND 再创建 target 或跨设备 SetContent 天然支持原子交接。
  该部分须先做独立 API 验证，再选保留 target 的事务交换或等价可回滚方案。
- 只有提交成功后，才更换窗口当前世代和默认新窗口世代；旧窗口/预览资源按其实际
  引用逐个退休，不提前销毁共享设备。
- 窗口内容、焦点、选中项、滚动位置、视频播放位置、预览 host 和操作任务不得重置。
  新建窗口若处于迁移期间，必须绑定明确的稳定世代，不能混用缓存。
- 若提交或硬件首次 Present 失败，撤销候选并继续旧完整帧。真正的设备丢失仍使用
  故障恢复状态机，不能与“健康设备主动升级”共用一个 `device_lost_` 标志。

## 状态与生命周期约束

建议状态为：默认路径 / 临时 WARP / 等待硬件 / 准备候选 / 提交候选 /
硬件稳定 / 保持 WARP。失败原因单独记录。最多一次自动升级尝试；重试需明确策略。

- 环境变量未设、为 0 或其他值：完全保留默认路径。
- 硬件失败或实际返回 WARP：不得进入升级循环。
- 窗口提前关闭：销毁窗口自己的候选和计时器；驱动工作线程只完成进程级结果发布，
  不向已销毁/句柄复用后的窗口投递指针。现有不可中断的驱动创建不能在 UI 线程 join。
- 多窗口、预览或操作窗已创建：不能通过 `users == 1` 的侥幸条件决定正确性；要么
  真正支持多世代并存，要么整个使用者集合采用已验证的协调交接。
- 最小化、DPI/尺寸变化、主题切换与设备丢失均可能发生在准备期间；候选需要窗口
  generation/尺寸戳，过期候选只能作废，不能提交。
- 不能承诺 WARP→硬件像素完全不变：已有实验观察到渲染差异。无空白帧与无可见
  视觉跳变是不同条件，都必须测量，不能把前者通过写成后者通过。

## 涉及文件

| 文件 | 所需工作 |
| --- | --- |
| `src/ui/ui_compositor.h/.cpp` | 世代所有权、明确 backend 的非阻塞预取、候选资源、提交/回滚、DComp 交接 |
| `src/app/app_main.cpp` | 仅实验变量门控、帧边界调度、窗口关闭清理、全量首帧与真实输入 trace |
| `src/ui/ui_renderer.cpp` | renderer 资源世代与候选失效边界，不能破坏现有设备恢复 |
| `src/ui/render_caches.h` 及相关图标/缩略图缓存 | 共享 CPU 数据与按设备归属 GPU 数据，异步结果世代检查 |
| `src/ui/ui_hover_preview.cpp` | 活动视频帧/预览位图设备交接与播放连续性 |
| `src/ui/quick_preview_window.cpp`、`src/ui/file_operation_dialog.cpp` | 共享使用者迁移、首用/已打开窗口、失败回滚 |
| `src/bench/` | 独立交接状态与故障注入测试，不启用完整历史 selftest |

这已经是图形资源生命周期改造，而不是一个安全的启动开关补丁。

## 实现前后的验收

1. 独立 DComp 交接验证：旧帧保持、新帧提交、每个创建/呈现阶段失败可回滚；逐帧捕获
   确认无空白/透明闪烁。没有这项证据不接入真实主窗口。
2. 世代生命周期测试：两个主窗口、未显示/已显示 Quick Look、操作窗和对话框共享；
   一方关闭或恢复不泄漏/悬空另一方资源；异步解码在迁移前后返回均不跨设备绘制。
3. 故障与取消：硬件慢、硬件失败、硬件回退 WARP、WARP 创建失败、候选 EndDraw/
   Present 失败、迁移期间真实设备丢失、窗口关闭/新开、尺寸/DPI/主题变化。
4. 功能：迁移前后真实 Ctrl+L、列表键盘选择、Space、视频预览、操作任务进度；焦点与
   文件列表内容一致。不得只用 WM_NULL 或 IsWindowVisible 证明“可用”。
5. 视觉：默认路径逐像素基线不变；实验路径单独检查 light/dark、100%/150%、透明
   backdrop、缩略图、视频、弹窗和跨窗口背景采样，记录 WARP/HW 渲染差异。
6. 性能：同源码、同目录、隔离配置交替 A/B；报告完整首帧、列表就绪、真实输入延迟、
   首次预览、迁移本身耗时、迁移期最长帧及迁移后稳定帧。包括额外内存与双设备峰值，
   不能只报 WARP 创建设备快了多少。设备创建、OS loader、渲染与输入法时间分开。

本轮没有实现迁移，因此也没有迁移构建、功能测试或性能通过结果。
