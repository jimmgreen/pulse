Changes in this work:
- Foreground window covering its monitor (including oversized borders), or
  unavailable foreground geometry: do not enqueue a direct Pulse request and
  do not swallow the chord. The native system entry owns the request; if it
  produces an Explorer window, the existing watcher still performs the strict
  prepared -> close -> observed destruction -> commit sequence. Failure keeps
  the source and cancels the staged Pulse handoff. This is not disabling the
  watcher or unconditionally closing a later unrelated Explorer window.
- Normal/windowed and work-area-maximized foregrounds keep the existing direct
  WinE route. Native-route decisions emit win_e_native_route/foreground_pid.
- Removing the per-window identity property alone no longer counts as source
  destruction. Require HWND disappearance or a different owner process/thread.
  Same-process/thread HWND reuse conservatively times out rather than risking
  a false commit. Close timeouts emit explorer_source_close_unconfirmed with
  request_id, source_exists, marker_matches, source_pid.
- Existing cancellation/deadline/Closed gating is retained. No timeout path
  was changed to force-open Pulse.
