# 自动打开/保存接入测试版 R42

## 目标和实际范围

应用从桌面或开始菜单正常启动时，经当前用户 COM FileOpenDialog/FileSaveDialog 创建的窗口进入已有 Pulse 包装层，不再要求逐应用经受管启动器启动。当前构建只提供 x64、当前用户普通权限；不改 HKLM、不绕过管理员、AppContainer 或受限令牌。旧式 GetOpenFileName/GetSaveFileName、自绘窗口、直接调用系统类工厂及某些代理进程不保证覆盖，必须按实际日志判定。

注册是用户级覆盖系统两类 COM 入口，不是 Windows 提供的“默认文件选择器”设置。系统原生工厂通过绝对 System32/comdlg32.dll 的导出取得，避免递归；原生 HRESULT、事件、自定义控件和过滤限制继续走已有契约。禁用状态及不支持的请求回原生。已缓存的对象在 Show 时重新检查开关。

## 模块

- dialog_auto_registration：64位用户注册视图、双键归属校验、启停阶段记录、重复操作与冲突保留；变更串行化。首次发现已有用户级同CLSID注册时拒绝覆盖。
- file_dialog_auto_server：独立 COM 工厂、原生工厂转发，复用 R41 provider/contract；不加载 Detours、不扫描或远程注入进程。工厂可缓存，创建时在当前 apartment 构造对应原生工厂。
- dialog_management_controller/settings：后台验证包、启停和状态；首次页面查询状态；既有受管启动作为单独功能保留。
- PulseDialogAutoControl：独立状态/停用入口；不依赖主程序窗口或正在运行的应用。

## 日志与测试包

复用 common/runtime_log，写入 `%LOCALAPPDATA%/Pulse/Diagnostics/Runtime/dialog_auto-<pid>.jsonl` 与 control 日志。记录激活、契约枚举/调用编号、原生回退、Pulse Show及返回码；2MiB轮转、有界队列。固定字段不记录所选文件名、内容；native reason以FNV64标识，源码对应字符串用于定位。无日志不证明应用曾调用标准入口。

单独解压包包括固定 Bundle、Start-Pulse.cmd、Restore-Native.cmd、Collect-Logs.cmd/.ps1。收集仅本地复制，不上传。启用后不能移动或删除组件目录，必须先恢复原生；此阶段不改正式安装器/升级卸载流程，不能直接作为正式全覆盖发布。

## 代价与后续边界

标准接口自动接入增加每进程一个COM模块和按需Pulse UI模块；沿用进程内事件语义，意味着UI故障会影响宿主，不能声称进程隔离。停用不强制卸载已装载DLL、不关闭用户应用。x86需匹配UI/文字组件及独立32位注册，管理员和受限应用需单独验证，不通过放宽令牌检查冒充支持。传统接口仍是后续入口工作，不能由本次COM自动接入推定全部原生对话框均被替换。
