# 安装包体积审计（2026-10-30）

基线：58集成版 `dist/PulseSetup-1.0.58-resident-batch.exe`。本次只做包内容核对、PE结构分析和隔离压缩实验，不删除正式功能、不覆盖安装包、不修改构建选项。

## 为什么有9.68MiB

- 完整安装包10,152,576B；安装器513,024B；XZ载荷9,639,492B；原始载荷33,291,816B（31.75MiB）。共33个文件，包含必要许可证。
- 打包使用明确白名单，build目录的测试程序、旧版对照exe、PDB、map没有入包。
- 已有X86过滤器、LZMA2 extreme9及整包固实压缩；多个程序的相似静态库已经可以共享压缩历史。先前将字典64MiB降至32MiB降低了解压提交额度，包体不变，不应再作为未做项。
- `pulse.exe` 15,467,008B，其中.text 12,070,400B、.rdata 2,045,440B、.rsrc 701,440B；主要是代码，不是图片。资源脚本44个ICON/RCDATA源文件合计155,937B，图标69,976B、Logo11,601B，未发现嵌入大字体。资源源文件合计与最终资源段不同，后者还含字符串等。
- PDFium 7,370,752B；内容搜索2,616,320B；文件名索引2,050,048B；LumaText1,648,640B；预览宿主1,407,488B。原始大小不能直接当作压缩包可省空间。

## 已有优化，不重复承诺

18个设置/编辑/对话框源使用尺寸优化；SQLite已裁剪并使用尺寸优化；LumaText已有专门体积优化。PDFium的本地固定配置已经关闭V8和XFA。此前主程序IPO试验增加体积且无稳定启动收益，目前关闭。删除多语言/许可证、降低预览能力或取消进程隔离，不作为无损减重。

## 真实压缩对照

实验使用同一批当前二进制、同一压缩参数、同一安装器大小，重新构建manifest和压缩载荷，解压后核对每个保留文件的内容及SHA-256。下表为相应载荷的等效安装包大小，**不是可以直接发布的精简安装器**；当前PDF加载器要求安装目录存在pdfium.dll，缺失时功能会不可用。没有安装测试，也没有实现按需PDF下载。

## 选择与实施顺序

1. 明显减小下载包：保留完整离线包，另提供按需增强的精简包。PDF引擎是最大单项；需要补齐版本固定、下载校验、取消/重试、离线提示，以及PDF预览和文字提取共同的引擎查找路径。首次使用会多一次下载，模块装好后继续使用原引擎；安装后总占用不会等量下降。必须验证后才能发布。
2. 内容搜索/文档提取/AI已有增强包下载架构，但当前发布清单明确为本地同版本可用而内置，不能仅凭旧头文件注释直接删除。测得仅拆这三项的收益有限，不值得当作“大幅压缩”单独交付。
3. 完整离线功能不变：下一批试验冷路径代码尺寸，优先批量重命名界面、AI对话面板及AI动作模块。现有map相邻地址粗估代码贡献约189KB/138KB/113KB，**不是可节省量**；逐个改编译策略后检查真实包体和相关交互。列表、排序、绘制热路径维持速度优先。不能提前承诺下降几MB。
4. 数据表存储形式、共享代码等只有证明压缩包或安装后占用有效改善才实施；不为体积数字给启动和首次预览增加运行时解压成本。
