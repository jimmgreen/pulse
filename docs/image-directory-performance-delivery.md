## 本次实现

- 普通网格按窗口维护当前需求，绘制中保留新旧需求并集；其他窗口仍需要的内容不会被取消。清除无需求队列，解码等待过程中取消旧任务，发布前再次验证；取消不产生坏文件负缓存。完成通知只失效仍订阅的窗口，由 Win32 合并更新区域。
- GPU 上传移出缓存共享锁；以独立像素所有权、上传令牌和设备代际验证发布。每帧采用 3ms / 4MiB 实验预算；预算不足延到后续帧，失败可重试，不重复请求已有 CPU 像素。
- GIF 网格独立首帧入口按需读取前缀，不建立后续动画帧表、不保留动画缓存。首帧输入前缀上限 16MiB、估算工作集上限 192MiB、输出边长上限 512；原尺寸画布仍存在。透明度、背景、偏移与动画首帧保持一致；预算失败保留限频重试。
- 磁盘缓存改为独立 writer，排队最多 64 项、像素预算 16MiB（含处理中项）。队满丢弃持久化，不阻塞出图；请求持有自己的路径和像素。保留原缓存格式及可移动介质策略。服务采用进程生命周期，退出不等待不可控写盘，临时文件沿用原恢复规则。
- 照片墙只在本来源实际比例变化时递增 revision；布局计算转到单 running / 单可替换 pending 后台任务，generation 校验并合作取消。每个窗口/窗格独立，旧任务不能替换最新输入。布局发布与同一不可变快照内的滚动锚点更新一起进行；绘制和命中使用相同布局。
- 增加目录枚举、排序及快照应用阶段事件，复用不记录文件路径的数值诊断接口。

## 第二轮重构

- 照片墙首次路径键、比例来源表、过滤投影和行布局全部由后台任务构建；UI 只提交不可变快照与过滤句柄。稳定版本不再遍历全部文件。比例变化通过有界日志和反向映射更新相关项目；无关变化不触发全量查找和重排。大来源表释放也移出 UI。
- 比例探测按视图保存最新需求，优先可见 384 项和邻近 128 项；深滚动替换旧需求，多窗口轮转。离开视图、导航和关闭清除需求，结果按路径/mtime/size 检查版本；过期结果不发布。通知按存活窗口合并。
- 静态网格图片增加主进程共享解码预约：默认 1GiB，环境变量 PULSE_GRID_DECODE_BUDGET_MIB 可设 32～4096MiB。宿主先申请再分配主要像素缓冲，JPEG 原生缩放/DC、PNG 行解码、TIFF 段缓冲采用不同估计；回退前升级预约，未知路径限制为单任务。竞争时有界退避重排，取消、失败及宿主终止释放预约，资源拒绝不永久标为坏文件。
- 保留第一轮的需求取消、上传预算、GIF 首帧与异步持久化。这些网格改动针对旧任务占道、共享锁及同步写盘；不能仅由照片墙基准推断网格吞吐提升。

## 交付边界

- 解码预约控制估算的任务缓冲，**不是整个进程组的硬内存上限**。第三方 codec 的元数据调用可能提前分配；详情动画、视频、PDF、GPU 缓存未纳入统一硬限制。
- 照片墙 Shell 属性探测仍可能被第三方处理器阻塞；失效结果会丢弃，但未增加进程隔离。相关比例变化的行布局仍在后台重建，不是局部行修补。
- 未引入增量目录快照；尚无证据表明枚举是反馈场景的主瓶颈。
- 未拥有真实反馈目录、HDD/NAS、不同 GPU/低内存机器的冷暖缓存 p95 矩阵。不把合成验证写成该矩阵通过。
