# Pulse 索引位置故障：用户诊断（工具 1.2）

当前尚未确认用户电脑上的根因，以下脚本用于收集定位证据，**不是清除索引或自动修复脚本**。

## 会收集什么

- PulseIndex 服务的状态、退出码和运行账号类型。
- 安装目录内 Pulse 主程序和索引服务的文件版本。
- 索引目录是否存在、是否为链接、目录权限摘要；完整目录名不会写入报告。
- 磁盘文件系统类型、剩余空间与系统版本。
- 已存在的索引运行日志中的固定事件名和数字字段，不直接复制完整日志。
- 可选：使用与索引程序相同的打开方式，检查 NTFS/MFT 和 USN 的少量**文件系统元数据**。不输出文件名或文档内容，不进行整盘遍历。

脚本**不会**停止或启动服务、修改权限、建立 USN 日志、删除索引、修改设置、读取文档内容或自动上传。它只会在脚本所在目录创建一个新的 `PulseIndexReport-*.json` 文件。

## 一键运行

解压后双击 `运行诊断.cmd` 即可收集普通诊断。若需要底层磁盘元数据检查，由用户自行右键该文件选择“以管理员身份运行”。脚本不会自动提权；普通运行时会跳过需要管理员权限的项目。

## 普通诊断

把 `diagnose_index_storage.ps1` 放在可写的本机文件夹中，从该文件夹打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\diagnose_index_storage.ps1
```

`ExecutionPolicy Bypass` 仅作用于本次子进程，不修改电脑的持久执行策略。脚本自动读取 Pulse 的索引位置配置。如果没有找到配置，也可显式提供设置中显示的路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\diagnose_index_storage.ps1 -IndexDirectory 'D:\你设置的索引文件夹'
```

## 补充底层扫描诊断

若问题是“索引扫描未完成”，请用户**自行**打开管理员 PowerShell，在脚本目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\diagnose_index_storage.ps1 -ProbeVolumes
```

脚本不会自行提权。如果没有管理员权限，会跳过底层磁盘元数据检查并在报告注明。普通用户不能检查私有索引目录，**不等于** SYSTEM 索引服务也没有权限，请不要据此手动放宽索引目录权限。

## 回传

先打开并检查生成的 JSON，确认无不希望共享的信息，再把这个 JSON 回传。**不要上传索引数据库、整盘文件列表、文档或账号凭据。**

尚未启用运行日志、没有权限访问日志，或某项探测返回失败，都将作为诊断限制记录，不会被当作根因已经确认。

## 扫描失败证据保留

1.2 版按最后修改时间选择最新的 3 个索引日志文件，逐行读取，每个文件分别保留最近 64 条重建开始、重建结束或卷扫描失败事件，以及最近 16 条其他白名单事件。报告最多 240 条，最新文件优先，同一文件内按原顺序排列；后续大量健康心跳不会挤掉保留的扫描失败证据。超过保留数量或已轮转删除的历史仍可能缺失，缺少事件不代表扫描成功。

新版索引服务的 `index_volume_scan_failed` 事件仅导出数字字段：`drive` 为盘符字符码（例如 68 表示 D），`phase` 为失败阶段，`records` 为当时记录数，`limit` 为容量上限，`error` 为错误码。阶段编号：1 打开卷，2 原始 MFT 扫描停止，3 USN 读取，4 USN 页面检查，5 容量限制，6 空结果或取消，7 构建索引树。旧服务日志没有此事件时，仍需结合重建事件和探测结果判断，工具不会从缺失信息推断根因。字符串路径和嵌套字段不会导出。

## 启动参数修正

1.1 版启动器不再传递以反斜杠结尾的 `-OutputDirectory`，避免 Windows 本机参数解析将结束引号混入路径。旧版启动失败时尚未完成报告生成；无需修改索引配置。

1.2 版另在参数绑定完成后设置默认输出目录，兼容 Windows PowerShell 尚未填充 `$PSScriptRoot` 就求值参数默认值的情况。省略 `-OutputDirectory` 时仍写入脚本所在目录。
