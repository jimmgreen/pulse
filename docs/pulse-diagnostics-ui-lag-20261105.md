### 补充截图：一个慢帧几乎全部耗在绘制区段

已对照 `src/app/app_runtime.cpp` 的状态栏格式和 `src/app/app_main.cpp` 的计时边界：

- DEV 是最近完成帧的 Render 总耗时；D 为 BeginDraw 前至 EndDraw 返回后的墙钟耗时；P 为呈现区段耗时。状态栏构建发生在当前帧完成之前，显示的是此前完成的采样，不是截图正在绘制的这一帧。
- D 占该总帧耗时约 99.85%。该慢帧的 Present 区段只有 0.2ms；现有证据将排查重点放在绘制区段。

- 枚举/排序是最近一次目录任务的采样，不是本帧子阶段，也不能与 D/P 相加。不过它们同样显示目录任务很短。
- FPS 是约 1 秒活动窗口内的平滑帧率，不是 1000/DEV；因此 87 FPS 与一次 233ms 慢帧可以同时出现。高平均 FPS 不能反驳瞬时卡顿。如果每帧都要 233ms，持续吞吐才约为 4.3 FPS；单张图没有证明持续如此。

- 截图没有时间戳，不能把这个慢帧与日志中 generation 63/65 的延迟认定为同一次事件；截图也没有记录慢帧频率。

## 源码对应关系与待验证原因

当前工作区仅作为解释事件语义和确定采集点的参考，不等同于日志中二进制的精确源码快照。

1. `src/app/app_worker.cpp`：记录后台 navigation_end 后调用结果回调。
2. `src/app/app_runtime.cpp` 的 PostWorkerResult：入队并 PostMessage WM_WORKER_RESULT。
3. `src/app/app_main.cpp` 的 WM_WORKER_RESULT：调用 ProcessPendingResults，随后请求重绘。
4. `src/app/app_navigation.cpp`：应用阶段记录 navigation_snapshot_applied；未记录这一结果对应的首次成功 Present。
5. `src/app/app_main.cpp` 的 Render：在主线程构建视图、绘制并执行 EndDraw/Present。慢帧可能同时推迟输入、结果应用与动画。
6. `src/ui/ui_compositor.cpp`：Present(1,0)/Present1(1,0) 同步呈现；硬件 D3D 创建失败时回退 WARP。两条路径均为候选，诊断包没有记录设备类型、适配器、GPU 使用率或呈现耗时，不能认定该用户实际触发了其中哪一种。
7. `src/app/frame_pump.cpp`：通过合成器时钟、DWM 或定时器调度帧。包内没有该用户实际选中的时钟和唤醒间隔。

补充截图后的排查优先级：先拆分 D 区段中的 BuildVm、文字、列表场景、hover 覆盖层与 EndDraw；特别区分 EndDraw 内部等待和调用前的 CPU 工作。主线程慢消息与帧调度作为其他延迟的补充采集项。文字测量/光栅化、hover 卡片和 Shell 预取只有在调用栈或阶段计时命中后才能归因。
