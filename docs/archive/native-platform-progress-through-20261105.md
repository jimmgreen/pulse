# Pulse 原生增强包开放能力与 AI 协同实施方案

修订日期：2026-11-05。主线：**C++ 原生 DLL 插件 + 版本化 C ABI + C++ SDK**。

## 1. 目标与责任边界

用户要求：**开放 Pulse 的 UI 能力和可复用 API，其他逻辑由开发者自己编写，性能必须好。**

Pulse 维护原生组件、稳定接口、内部服务适配和插件生命周期；开发者维护插件业务、算法、数据源及界面组合。开发者修改 DLL 即可改变行为，无需改 Pulse 源码。AI 是使用同一 SDK 的开发助手，不是插件运行的前置条件。

旧方案中“声明式工作流优先、JavaScript 作为后续主运行层”的顺序被本修订取代。原文保留在仓库 docs/archive，旧测试和归档保留为历史证据，不能作为原生 SDK 的完成证明。

## 2. 架构决定

- 主线：受用户信任的 C++ DLL，宿主内按需加载，直接函数调用。无需每次命令启动进程、JSON或IPC。
- 二进制边界：固定导出入口、版本和结构大小协商、模块化函数表、固定宽度数值、明确编码的字符串与长度、稳定句柄。禁止依赖私有头文件、AppState、STL跨DLL对象或跨边界异常。
- C++ SDK：类型化包装、RAII资源和订阅。插件内可使用自己的C++库；边界明确谁分配谁释放、线程、取消与回调寿命。
- UI：真实Pulse控件与布局，支持代码创建、增量修改、事件订阅和自定义数据；禁止只提供近似外观控件或静态预置命令。
- 服务：上下文、文件、导航、搜索、预览、标签、任务、设置、AI逐项进入能力台账，适配已有引擎，不复制实现。暂未开放的接口必须明确列出，不能返回空成功。
- 生命周期：发现、版本检查、加载、激活、停用、取消、注销事件和UI、等待在途回调，再销毁。首版不承诺任意时刻热卸载；无法安全卸载时要求重启。
- 可信原生DLL不是沙箱：它拥有当前进程权限，错误可能影响Pulse。API权限约束不能限制恶意DLL。确需隔离的解析任务可另设原生worker，不强制每个插件使用独立进程。
- JavaScript代码保留为开发实验，不再扩展为主线，也不是正式SDK必需依赖。

## 3. 状态口径

- **已验证（限定范围）**：有实际测试或应用内验证证据，只证明列出的范围。
- **已实现待验证**：已有代码，未完成对应集成和实际运行验收。
- **进行中**：正在实现，接口尚不能当稳定发布承诺。
- **未完成**：尚无可交付实现或证据不足。
- **历史/实验**：保留参考，不计入C++原生SDK完成度。

编译成功不等于功能通过；内部存在控件/服务不等于已经对DLL开放；接口数量不作为完成标准。

## 6. 性能约束

滚动、绘制、布局、输入即时反馈不等待跨进程业务调用。耗时磁盘、解析与算法在后台执行，插件结果异步回到UI。文件接口支持批量、分页和取消，避免重复枚举或逐文件跨边界往返。未启用插件时不启动运行层，不加载脚本引擎。

测量必须注明系统、硬件、编译配置、样本数和冷热状态，分别报告主进程和插件/进程组内存。相同算法、文件集及宿主引擎对比原生入口和插件入口。旧方案数值预算是研发目标，不是已测结果；先记录基线，再根据实测确定具体预算。
