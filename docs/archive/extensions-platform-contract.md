# Pulse 原生增强包平台契约

目标与阶段只维护在 [主路线图](../Pulse-增强包开放能力与AI协同实施方案-2026-11-02.md)。本页维护架构规则，不重复状态日志。

## 宿主与增强包的分工

Pulse 开放真实 UI 组件、布局、挂载位置和可复用服务；开发者在增强包中实现业务算法、数据组织和交互。新业务不应要求宿主增加一条专用命令才能实现。

执行主线为 C++ DLL + 版本化 C ABI + C++ SDK。JavaScript 实验执行层已经退役，相关旧清单和启动入口明确拒绝；JSON/TypeScript 元数据仍用于描述契约，不提供脚本执行。

DLL 内可使用自己的 C++ 库和后台线程；公开边界不传 AppState、内部控件对象、STL 对象、异常或跨 CRT 释放的内存。使用固定宽度字段、明确编码/长度、句柄与函数表，按结构大小和接口版本协商。当前是开发预览，不提前承诺长期 ABI 兼容。

## UI 与挂载

- 绘制、输入、布局和即时反馈由 Pulse 原生组件完成；不另造近似外观组件。
- 插件负责界面组合、状态、数据和业务行为，支持程序化创建/更新，不能只开放固定菜单点击。
- 组件类型、贡献点和承载面是不同能力：能创建表格不等于能挂到侧栏，更不等于已有桌面接管接口。
- 当前原生插件页面、事件和模型的支持范围以公开头与机器清单为准；动态提供者和更多挂载点必须分别实现并验收。
- 未来桌面磁贴场景应复用通用 surface、文件/变化事件和拖放能力；磁贴分组与布局算法归插件，不能写成宿主专用业务。

## 服务与线程

公开服务按模块查询，明确输入、结果、主体、线程、拥有权、取消及失败语义。已有内部命令、JSON broker 或元数据不自动成为 C++ 公共服务。

批量操作优先分页、批量、异步和增量更新。阻塞文件、Shell、网络与耗时解析不得移到 UI 线程。插件后台结果通过受控派发回到拥有 UI 的线程；取消和代际变化应抑制旧结果。

文件修改沿已有宿主计划/确认/提交/任务路径执行；任务被接受不是最终成功。对尚未支持的字段或接口返回明确错误，不返回空成功。

## 分发与生命周期

当前单 DLL `.pulse-ext` v2 支持声明、哈希绑定、安装、显式启用、默认发现、正常入口按需激活和重启升级/回退。详细契约见 [原生包说明](../native-packages.md)。额外私有 DLL/资源与完整图形管理器尚未完成。

同进程 DLL 拥有当前进程权限，API 主体检查不构成原生代码沙箱。发现和验证不执行插件；用户明确启用后才允许正常激活。

停用先阻止新调用，再注销 UI/事件、取消任务，并等待在途回调及插件线程按契约结束；随后销毁实例和卸载。运行中的 DLL 不热替换，版本更新在重启后生效。桌面承载实现后还必须验证退出恢复、焦点与输入状态释放。

## 性能和交付证据

高频 UI 不等待每次跨进程业务调用。原生接口路径直接调用；模型提交仍可能同步复制并复用内存 DOM 校验，内部服务也可能复用 JSON 模型，不宣称整条路径零复制或零序列化。

测量区分无插件基线、首次激活、持续更新、后台派发、批量吞吐、内存与退出回收；注明环境、输入和冷热状态。已有暖态优化数据只证明对应归档，不是所有插件的性能承诺。

每个交付版本应有匹配源码、宿主、SDK、机器清单和实际行为证据。UI 用应用内截图；测试只覆盖本次影响范围，编译、模型检查、截图和文件行为各自报告。具体阶段与剩余项只回写主路线图。
