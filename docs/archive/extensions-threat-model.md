# 增强包开发预览的信任边界

本文仅描述声明式 API v1 的数据与宿主服务权限边界；签名、原生执行和公开 API 覆盖分别由对应契约定义。公开能力及支持条件以 `describe_extension_api` 返回的 Schema、`developerFeatures` 和能力详情为准。

## 主体与资产

保护对象包括用户文件、Pulse 配置、其他包的状态、窗口归属、一次确认的输入，以及主程序的可用性。清单、包名、命令标题、文件名和第三方说明都是数据；不能成为授权或 AI 指令的来源。

| 来源 | 当前信任 | 可以决定 | 不可以决定 |
| --- | --- | --- | --- |
| Pulse 核心与已编译适配器 | 受信任实现 | 公开白名单、宿主主体、确认、队列及资源核验 | 以路径检查替代实际操作时的身份约束 |
| JSON 增强包 | 未验证来源的声明数据 | 已知命令、有限 UI 属性、显示字段 | 自报可信身份、运行脚本、调用内部菜单编号、伪造确认 |
| 用户原生操作 | 本次明确交互 | 启用包、选择文件、确认具体计划、取消任务 | 一次安装授权自动覆盖之后所有文件操作 |
| AI／MCP | 独立受控调用来源 | 发现契约、校验清单及已有工具允许的操作 | 借自身身份给增强包增权，或把模型回答当作用户确认 |
| 文件系统 | 可变化的外部状态 | 返回当前对象与错误 | 保证名称对应的对象从预览到执行始终不变 |

声明式清单自身不执行代码或表达式。另行声明并显式启用的 native DLL 会在 Pulse 进程中执行；本页的数据权限模型不限制 DLL 直接使用 OS 权限。JavaScript 执行层已删除。

## 已实现的边界

| 风险 | 当前约束 | 验证位置／剩余边界 |
| --- | --- | --- |
| 非法或过量输入 | 64 KiB 清单、严格未知字段/参数拒绝、32命令、8按钮、3字段、4组；UTF-8与标识符约束 | manifest与生成契约测试；不是通用JSON执行器 |
| 冒充其他包／窗口 | 宿主捕获版本哈希、generation、owner incarnation与grantEpoch；内部Binding不能从JSON构造 | authorization/runtime测试；哈希证明内容版本，不证明发布者 |
| 停用后使用旧回调 | 启停、重载及owner注销撤销原Binding；新点击只能由仍有效绑定申请短期Lease | runtime、工作区与文件UI探针；已完成操作不回滚 |
| 确认重放或替换输入 | UI冻结输入，worker记录身份，不可变计划摘要；Store确认后一次消费，ExecutionPermit共享一次启动门 | transfer_plan与preparation测试；确认凭据不公开传给包 |
| 文件名／路径替换 | 逐级相对句柄打开，拒绝重解析点；复核源对象/父目录/目标目录及必要版本信息 | snapshot测试，含同名替换与父目录替换；不是恶意同用户进程的完整隔离 |
| 覆盖现有文件 | 目标目录句柄下随机暂存，最终同句柄无覆盖提交 | controlled_transfer测试；多项不是原子事务，后项失败保留前项结果 |
| 移动中断导致假报成功 | 提交目标后才删除已核验源句柄；失败时报告目标已提交而源保留 | 执行器及队列readonly移动测试；不承诺自动回滚 |
| 丢失安全元数据 | 拒绝所有命名流，包括Zone.Identifier；拒绝EFS、离线、稀疏、压缩等未支持特性 | 执行器定向测试；目标继承ACL，不声称复制源安全描述符或全部特性 |
| 取消影响其他任务 | 任务ID加原始/预期Binding双重核验，只设置对应任务取消标志 | controlled_ops真实worker测试；普通宿主全局取消仍属于用户入口 |
| 无确认恢复／重试 | 受控任务不写入普通恢复队列，不进入路径型自动重试或Undo | 队列journal/retry/undo测试；重试须重新计划并确认 |
| 误导确认内容 | 原生窗口保留完整canonical包ID，包名仅辅助；控制及双向字符显式转义，默认Cancel | confirmation测试及真实键盘/截图；长清单省略，Ctrl+C完整显示文本不是原始路径 |
| 无限制资源占用 | 最多32包、64owner、128 live tickets；计划32条/64源/有界路径和序列化大小，五分钟启动期限；受控排队32、终态保留16 | 各模型限额测试；同步文件系统调用无法由取消标志强制中断 |

文件执行源和祖先保持受限共享；目标执行目录允许write sharing以支持相对提交，但不允许delete sharing。实际目录对象在create/commit前复核，相对根变成junction的攻击夹具也必须保持拒绝。不能把一次属性查询当作与后续操作原子绑定的替代品。

大小与修改时间是版本线索，不是内容不可变证明。已有可写映射、同用户恶意程序、被攻破的核心、驱动或管理员不属于当前JSON包模型能够完整隔离的对手。脚本开放前必须重新建立进程、令牌、文件、网络、IPC与资源预算边界。

## AI 与数据边界

能力发现、Schema、TypeScript声明和MCP发现共用契约。发现不授予执行权限。新文件能力没有增加MCP执行工具；已有AI文件工具也不能把自己的确认或身份转交给增强包。

作者与AI应先发现能力，再生成白名单字段，再由真实宿主校验。提示词、README、包描述或文件正文中的“忽略限制”“自动确认”等文字只作为数据处理。当前这两个文件能力没有网络、上传、模型外发或包指定绝对路径入口。

## 已知限制与发布门槛

- 崩溃可能遗留随机暂存文件，移动也可能留下双份；无断电事务、可靠恢复日志或按路径自动清理保证。
- 受控终态只保留最近16条。NotFound表示未知、已淘汰或无权访问，不能解释成已成功或未修改。
- 本地安装包使用内容哈希和显式新增能力接受，没有发布者签名、信誉、自动更新或可信市场。
- 目前未在真实Windows 8.1设备验证，不把API兼容编译视为实机结论。
- 新文件能力仍是本地普通文件子集；递归、覆盖、通用ItemRef/ScopeRef、工作流DAG、脚本及统一AI执行都需要独立设计和验收。

具体测试数量、曾失败的检查、截图范围及日志见[维护指南](extensions-maintainer.md)。原生截图使用实际绘制逻辑；不透明主题背景的诊断截图不代表捕获了DWM透明材质或桌面合成结果。
