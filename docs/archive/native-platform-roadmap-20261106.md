# Pulse 原生增强包平台：目标、阶段与交付状态

更新日期：2026-11-06。**这是唯一主路线图。** 作者文档、接口参考和历史记录的入口见 [文档索引](extensions-index.md)。本页只记录当前决策与交付状态，不追加历次工作日志。

## 1. 最终目标

**开放 Pulse 的 UI 能力和可复用 API，开发者自己编写增强包，并能直接挂载到 Pulse。**

Pulse 提供组件、布局、挂载位置、版本化接口、内部服务和生命周期；开发者提供业务逻辑、算法、数据组织与界面组合。开发新功能应主要修改增强包，而不是要求 Pulse 为每个场景增加预置命令。

目标场景包含：目录分析、批量文件处理、自定义工作区，以及后续的**桌面磁贴增强包**——由插件组织桌面文档，以类似 Windows 10 磁贴的分组与布局呈现。后一个场景不是当前 SDK 已有能力，具体依赖见第 6 节。

完成标准：外部开发者只依赖公开 SDK 即可编译、打包、安装、挂载、更新和移除增强包；真实 UI 与宿主服务能支撑自己的业务；停用和退出能够释放资源；文档、机器清单与实际行为一致。

## 2. 已确定的技术路线

| 层 | 决定 | 责任 |
|---|---|---|
| 执行 | C++ 原生 DLL，宿主内按需加载 | 插件自行实现业务与后台算法 |
| 二进制边界 | 版本化 C ABI + C++ 薄封装 | Pulse 维护类型、错误、线程、对象寿命及兼容策略 |
| UI | 复用 Pulse 的真实控件和布局 | Pulse 管绘制/即时交互，插件组合界面并更新数据 |
| 挂载 | 统一挂载与生命周期，逐步增加贡献点 | 原生窗口、右侧栏、主内容工作区已经由 `pulse.ui.mount` V1 开放；桌面承载仍需专用接口 |
| 服务 | 模块化、类型化、可查询的 API | 复用现有引擎，支持异步、批量、分页及取消 |
| 分发 | manifest + 单 DLL 的 `.pulse-ext` v2 | 内容哈希校验、明确启用、升级/回退和诊断 |
| AI | 与人类开发者使用同一 SDK | 发现、开发、构建诊断、验证；不成为运行前提 |

**JavaScript 实验路线退役并清理实现，不再保留另一套可选运行层。** JSON 清单、声明式 UI 元数据以及 TypeScript 类型声明不是 JavaScript 执行引擎，可以继续服务于协议描述和宿主内部复用。旧 `runtime` 字段、`runtime.invoke` 和脚本启动参数必须明确拒绝，不能被静默忽略。

原生 DLL 与 Pulse 同进程。它不是沙箱，插件自己的崩溃可能影响宿主。首版只承诺经过生命周期协议的停用和销毁；运行中的版本升级通过重启生效。当前预览 ABI 不等于已经承诺长期稳定发行 ABI。

## 3. 当前能力：能做什么、缺什么

状态统一为：**已验证（写明范围） / 部分完成 / 未完成**。编译通过、结构声明存在和历史测试数字都不能替代功能验收。

| 能力 | 状态 | 当前交付范围 | 尚未完成 |
|---|---|---|---|
| 独立原生工程与生命周期 | 已验证 | 公开头、CMake 示例、入口协商、激活/停用/销毁；开发者 DLL 不链接 Pulse 内部库 | 长期 ABI 兼容矩阵与正式发布流程 |

## 5. 实施顺序与后续开发

按依赖推进。已交付项链接公开契约；待开发项的接口名称和签名需在实现评审后确定，不能视为已有 API。

1. **动态 UI 数据链路——基础已交付并验证**：`pulse.ui.data` V1 提供者注册/撤销、绑定/解除、版本一致的分页与增量、稳定 ID、筛选/排序请求、代际取消和关闭后拒绝发布。独立 live-data DLL 自己生成 4096 条数据、管理工作线程和算法；真实宿主验证分页、快速切换、增删改、空/错误、取消和停用。契约见 [动态数据指南](extensions-native-data.md)。真实目录来源和变化订阅已由下一项与目录工作台组合验证；长期持续更新压力仍未交付。
2. **目录与交互上下文——已交付并验证**：`pulse.directories` V1 提供显式绝对目录句柄、不可变快照、分页、合并失效监听和条目打开路由；`pulse.context` V1 提供所属宿主的已加载上下文及合并导航/选择事件。独立 directory-browser DLL 组合两者和真实数据表格，不包含私有头、自有枚举或 watch。真实宿主验证监听后的增删改、快速切换、空/错误、同数量多选变化、主窗口与插件目录独立、子目录正常导航打开、关闭及停用。契约见 [目录与上下文指南](extensions-native-directories.md)。监听是失效通知，不是精确变化日志；上下文按 30 ms 合并；打开接受不等于外部应用启动成功。
3. **文件服务补齐——基础范围部分交付，继续进行**：`pulse.fileops` V1/V2 与目录目标能力已交付；V3 以同一 attachment 的当前源目录快照 entry ID 提交普通文件到已打开目标目录；V4 追加目录树复制和逐文件结果。各版本保留既有 ABI 前缀，权限、机器清单、manifest schema、作者指南和适配器回归已同步。V3 独立 DLL 隔离真实宿主验收 54 PASS、0 FAIL；V4 隔离真实宿主验收 61 PASS、0 FAIL，覆盖嵌套文件/空目录、逐文件状态、既有目标冲突、确认、停用取消和应用内截图，报告见 `build-extensions/native-target-v4-20261106-02/report.json`。目录树复制基础路径已交付；下一步补 V4 尺寸/执行中取消/reparse 竞态强化，再做永久删除、图标/缩略图；搜索/预览、标签/收藏、AI 服务继续列入 M2。

## 6. 目标案例：桌面磁贴增强包

### 用户体验

- 用户安装并启用增强包，明确选择桌面模式；插件按自己的规则整理展示桌面文档。
- 文档以磁贴和分组呈现，支持大小/排序/拖动、打开、筛选与状态更新。
- 文件新增、删除或重命名后，界面按增量更新；布局在重启后恢复。
- “整理展示”默认只改变布局。移动、重命名或删除真实文件属于独立操作，须明确区分并走相应宿主流程。
- 用户停用或退出后，桌面正常恢复，插件窗口、订阅、后台任务和抓取状态均释放。

### Pulse 与插件各自实现什么

| Pulse SDK 提供 | 增强包开发者实现 |
|---|---|
| 真实 UI 原语、布局、主题/DPI、图标/缩略图 | 磁贴外观组合、分组规则、大小策略和排序算法 |
| 通用目录快照/变化事件、条目身份和文件服务 | 文档分类、搜索筛选策略、收藏与展示逻辑 |
| surface 创建/挂载/销毁、桌面承载生命周期 | 何时进入桌面模式、哪些内容与布局呈现 |
| 拖放/输入事件与文件操作确认链路 | 拖动后的布局调整或明确提出的文件操作 |
| 插件自有持久化、版本与诊断 | 布局数据模型、偏好与迁移规则 |

### 分步验收

1. 普通插件窗口中用真实组件完成磁贴网格和分组，独立修改 DLL 即可改变布局算法。
2. 接入真实桌面文档数据、增量通知、打开与拖放；测试空目录、文件消失、快速变化和取消。
3. 接入桌面承载，再验证多显示器、不同 DPI、焦点/键盘、层级、显示器变化与恢复。
4. 验证停用、退出、升级、异常中断后的恢复，不遗留不可见拦截窗口或后台任务。
5. 固定大目录/持续更新输入进行性能测量，并保存应用内截图与行为报告。

桌面参考场景五步目前仅有普通插件窗口中的业务布局基础可复用；桌面文档数据接入、桌面承载、多屏/拖放恢复与完整性能验收均未完成。当前目录工作台的窗口/侧栏/工作区截图不能算桌面场景验收。

## 7. 交付与状态更新规则

每次交付只更新对应状态、公开契约和证据链接；完整过程日志放历史记录。维护者负责接口和实现，作者负责业务；新增行为必须说明线程、寿命、取消、失败与兼容策略。

- 功能：检查真实行为与相关边界；编译成功不等于功能完成。
- UI：使用应用内截图，检查真实交互、布局和相关主题/DPI；不以重绘示意图验收。
- 性能：说明环境、样本、冷热状态与测量对象，不把一次微基准推广为所有插件的承诺。
- 分发：归档对应源码、宿主、SDK及报告；历史报告只证明对应版本。
- 移除能力：同步清理执行代码、构建依赖、元数据、工具、示例与专属测试，保留明确的拒绝用例。

当前交付入口：[原生 SDK 作者指南](extensions-sdk.md)。固定包 `dist/native-sdk-platform-20261105-01/` 同时包含可匹配的测试宿主、公开 SDK、C++ 工作台样例、作者 MCP 和验收报告；这是开发预览，不是生产安装包。
