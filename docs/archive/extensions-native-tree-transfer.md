# 原生目录树复制设计

本文定义 `pulse.fileops` 目录树复制契约。V4 ABI、manifest 权限、机器清单、计划/准备器和受控执行器已接入，并已由独立 DLL 完成真实宿主验收：61 项通过、0 项失败。验收覆盖嵌套文件、空目录、逐文件结果、既有目标冲突不覆盖、确认流程、停用取消和应用内截图。报告：`build-extensions/native-target-v4-20261106-02/report.json`。剩余工作是扩大竞态与边界矩阵，不影响本次已验证路径。

## 首版范围

- 只提供复制；不提供递归移动、永久删除、覆盖和合并。
- 源必须是同一 attachment 的 `pulse.directories` 当前快照中的普通目录 entry；拒绝重解析点、链接、虚拟路径、网络共享和过期快照。
- 目标必须是同一 attachment 打开的普通目录句柄。复制在目标内创建一个以源目录叶名称命名的新目录；该名称或其后代冲突时整请求在写入前失败。
- 单次树最多 128 个目录、512 个普通文件、总计划数据 1 MiB；超限失败且不截断。拒绝 EFS、稀疏/离线文件、命名流、压缩文件及不支持的属性。
- 文件与空目录均保留相对路径。确认前冻结所有源文件和目录身份、文件大小/修改时间、目标身份与总量；任何变化都使请求失败。
- 所有 SDK 调用仍在 owner UI 线程；遍历、验证和文件 I/O 在 Pulse worker。一次 Pulse 原生确认覆盖整棵树。
- 执行按文件提交且不是事务。取消、进程退出或文件系统错误可能留下已提交文件和空目录；结果必须逐项报告成功/失败及剩余暂存项，不得声称回滚。

## 必须采用的执行模型

1. 源树遍历以目录句柄为根，通过相对名称枚举和打开子项；每层使用 `FILE_OPEN_REPARSE_POINT`，读取属性标签并拒绝所有 reparse 项。不得用递归路径拼接后直接复制。
2. 遍历期间为每个目录保存 file ID/volume identity；每个文件保存自身 identity、父目录 identity、size、last-write 和相对目标名。确认计划摘要必须覆盖全部字段与顺序。
3. 计划发布前重新验证源目录快照仍当前、所有目录仍匹配身份、所有文件元数据未变。执行前再次通过受控句柄验证。
4. 目标新目录与子目录必须从已验证的目标句柄逐级相对创建；拒绝跟随 reparse，持有创建后目录句柄直至任务结束。所有文件先写入同目录暂存句柄，再以不覆盖方式相对提交。
5. 建目录和文件前先完成目标冲突预检；外部竞态仍按逐项结果处理，不允许覆盖。停用只发取消信号，不等待同步文件系统调用。

## ABI 与权限决策

新操作必须追加 `pulse.fileops` V4，不改动 V1/V2/V3 字段和偏移。新增函数使用源目录 ID、当前 snapshot ID、目录 entry ID、目标目录 ID 和请求 ID；不接收路径。必须新增独立 `files.transferDirectoryTree` 资源权限，并要求 `files.readDirectory`、`files.transferToDirectory`、`operations.own`。普通文件 `submit_entries` 保持 V3 语义，不悄悄接受目录。

V4 使用 additive `submit_directory_tree` 与 `get_item`。后者先报告所需 UTF-8 相对路径缓冲区，再返回逐文件状态、字节和系统错误；最终文件项读取后释放保留结果。空文件树由终态 `get` 直接消费。V1/V2/V3 函数表布局保持不变。

- 公开独立 DLL：打开源/目标、枚举树、提交一次请求、观察确认与逐项结果。
- 真实宿主：普通嵌套树和空目录成功；文件名重复/目标已存在不覆盖；reparse/junction、刷新快照、替换源目录、文件元数据变化均拒绝；确认取消、执行取消、关闭句柄、停用和宿主退出符合文档。
- 独立隔离样本对源/目标逐文件及目录清单计算哈希；失败测试核对既有目标哨兵和所有保留的部分结果。
