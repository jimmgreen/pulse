## 本轮落地

- **D1 后台删除预检**：`DeletePaths` 只捕获请求并显示可取消准备窗口，属性、位置、回收站策略查询在后台执行。取消、替换请求、关闭所属窗口、异常都不能提交旧结果；确认窗口返回后重新核对所属窗口和请求。执行层使用自己的策略查询，不把 UI 预检结果当执行授权或永久有效缓存。
- **C1/C2 后续发现文件时建池**：累计新发现的小/中等文件，目录前缀不再让整项任务永久串行。重配之前先收齐旧池结果，再更换模式；稳定索引和作业自有路径保留。增加池重配诊断。
- **D2 有界永久删除**：按后序遍历边发现边删除，不再先收集整棵树。保留活动祖先帧，本地逐项执行；远程根保留最多 32 个普通文件的批次、最多 8 路 Windows 线程池工作。各根串行，每根独立判断设备，避免根并发和树内并发相乘。
- **D3/D4 和失败语义**：回收容量扫描在每个条目检查取消；合并重复策略查询；不支持 disposition 的缓存只属于本次根遍历。活动目录用包含目录读取权限、禁止共享删除的句柄保护，避免遍历时被改名替换。晚枚举失败/部分修改不自动整根重放，发送 refresh-only；未修改的普通权限错误保留原有提权路径。已在本请求完成的重复/后代根，仅再次确认不存在时跳过，使用保留大小写的集合与祖先查找，避免 O(N²) 扫描。
- **界面收尾**：准备窗口显示“删除 · 准备中”，不再显示复制统计/图表；取消按钮有效；再次创建窗口重新居中。

回收仍使用原回收接口，不转成静默永久删除；没有引入开源项目源码，也没有改变大文件复制内核或校验/移动耐久性语义。

## 性能数据与解释

同一 C: SSD、同样 10,000 个零字节文件分布在 10 个子目录，Release OpsManager 后端基准，各 3 次：

| 版本 | 三次总耗时（秒） | 中位数 |
|---|---|---|
| 本轮修改前永久删除实现 | 2.465 / 2.282 / 2.410 | 2.410 |
| 流式永久删除与目录保护 | 2.481 / 2.601 / 2.332 | 2.481 |

中位数约慢 2.9%，样本有限，不能宣称吞吐提升。新实现另一次 10,000 文件宽目录测试，约 **16 ms** 首次观察到 `f0` 消失，总耗时 **2453 ms**。它是任务提交后的轮询观测，不是精确内核 unlink 时间，也不是用户点击到首次变更；没有同条件旧版首变更数据，不虚报相对倍数。

本轮主要收益是 UI 不再同步等待预检、首次变更无需完整枚举、活动发现数据有界和取消/部分失败更可靠。帧数随目录深度增长，路径字符串和请求/日志仍占内存，不宣称全任务常量内存。

复制计时与其他构建/测试重叠，只作为功能证据，不用于提速结论。没有真实 SMB 服务器可用；远程批次机制通过本地强制并发测试，不能代替真实 SMB 吞吐、断线和 provider 兼容性验收。
