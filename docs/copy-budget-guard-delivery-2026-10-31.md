# 复制调度分配与备份保护（2026-10-31）

本轮接续 copy-followup，工作基线为 pulse58-integrated-fixes；不替代上一轮性能数据，也不代表整个原方案已全部验收。

## 实现

- **预算内联分配改造已决定撤回，不进入交付版本。** 实验将普通 1～4 资源放入栈内暂存并让租约持有稳定节点，确实消除预热路径的临时分配，但真实 SMB 对照退化。恢复上一版已验证调度实现，保留此前直接 UNC 受控并发。
- 替换异类目标/重解析点时，先在同一不共享 DELETE 的句柄上取得身份并重命名为备份；恢复和清理都核对身份。取消/失败不再按 original 路径递归删除新占用对象；仅实际恢复成功才移除完成记录。
- 文件及空目录备份可正常清理。非空目录保留并明确报错、显示路径：目录根身份不能证明其所有子项归本任务所有。这是有意的安全边界，会让“文件替换非空目录”保留原目录备份并报告清理未完成，不宣称原子回滚。
- 备份处理独立于普通复制协调循环编译，低频恢复函数禁止内联；此举减少代码展开，不单独宣称提速。
- 普通同类型文件 ReplaceFileW 覆盖路径未重构；冲突授权后目标变化、同身份原地修改、父目录竞争、完整撤销体系仍未解决。

## 已实际验证（含撤回实验，不等于全部进入交付）

- 预算预热后单资源、双资源各 10,000 次申请/释放，计数窗口内 C++ 堆分配均为 0。耗时约 2.745/4.677 ms，仅为微基准，不等于复制整体提速或软件常驻内存下降。
- 额度溢出资源、重哈希、所有者/identity 生命周期、move 覆盖、未知设备互斥、共享字节限制通过；复制池和六项故障注入复验通过。
- 备份文件被外部替换后拒绝清理/恢复，原位置被新对象占用时不覆盖；正常文件、只读文件、空目录恢复/清理通过，非空目录外部新增子项完整保留。
- 真实 OpsManager 集成：源目录覆盖文件成功且无备份残留；文件覆盖非空目录时只接受精确目录非空错误和保留路径，同时核验旧子项 SHA/属性/时间、新源目标 SHA/ADS/只读/时间。
- 首次非空目录集成因测试主线程设置英文 UI、复制 worker 保持系统语言而字符串比较失败，日志保留。改为独立 worker 格式化同一 ERROR_DIR_NOT_EMPTY，仍严格比对完整消息和路径，复验通过。基准 exe 不包含产品完整字符串资源，此项不等于最终 UI 视觉验收。

## 流式原因对照

8192 个 4 KiB 文件，各五轮随机顺序；完整规划/完整规划但保留源枚举句柄/真正流式，总耗时中位分别 3295.622/3225.239/2837.903 ms。完整规划样本 2861～6024 ms，显著波动；本轮流式方向与前轮回退相反，不能据此启用默认路径，也不能证明枚举句柄导致回退。全部 15 次源目标完整校验通过。保留 bench_data/copy_handle_probe_20261031 全部日志和样本，不删除慢样本。

流式仍默认关闭，当前证据不支持继续凭猜测修改系统复制 flags 或替换底层引擎。
