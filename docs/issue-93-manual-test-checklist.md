## 0. 准备（约 5 分钟）

### 0.1 安装与版本确认

1. 装包含本改动的构建（自己 `cmake --build` 出来的，或直接取本仓库 fork 的预发布 `v2026.10.5`）。
2. 启动后确认版本号与被测构建一致（fork 预发布显示为 **2026.10.5**）。若显示旧版本，说明装的是旧副本或装到了别的路径。
3. 建议用隔离实例跑测试，避免污染你日常的配置：

   ```powershell
   & "C:\Program Files\Pulse\Pulse.exe" --test-instance
   # 便携版：
   # .\Pulse.exe --test-instance
   ```

   隔离实例使用独立的偏好/状态存储，测完删掉即可。

### 0.2 造一个样本目录（一次性）

在 PowerShell 里执行，生成约 300 个混合名称的条目 + 一批中文名条目：

```powershell
$root = "$env:USERPROFILE\Desktop\pulse-typeahead-test"
New-Item -ItemType Directory -Force -Path $root | Out-Null
# 多个 a 开头项，用于验证「连按循环」
1..8   | ForEach-Object { New-Item -ItemType File "$root\apple-$_.txt"  -Force | Out-Null }
1..3   | ForEach-Object { New-Item -ItemType File "$root\Apricot-$_.txt" -Force | Out-Null }
1..5   | ForEach-Object { New-Item -ItemType File "$root\zebra-$_.log"  -Force | Out-Null }
1..4   | ForEach-Object { New-Item -ItemType File "$root\Banana-$_.md"  -Force | Out-Null }
# 特殊首字符
'.gitignore', '_private', '1-first' | ForEach-Object {
    New-Item -ItemType File "$root\$_" -Force | Out-Null
}
# 中文名
'文档-一.docx','文档-二.docx','图片-甲.png','音乐-乙.mp3' | ForEach-Object {
    New-Item -ItemType File "$root\$_" -Force | Out-Null
}
# 制造不同的修改时间，供「按修改日期排序」用例
Get-ChildItem $root | ForEach-Object { $_.LastWriteTime = (Get-Date).AddMinutes(-1 * (Get-Random -Max 2000)) }
```

> 性能用例（10 万行）单独放一个目录，见 §5.1，别和上面混在一起。

### 0.3 关键前提

每次按键前先**用鼠标点一下文件列表里的空白或某个条目**，确保焦点在列表而不是地址栏/搜索框。

## 8. 本版本**不在**范围内（测到也不算 bug）

- **多字符前缀**：连打 `ap` 不会收敛到 `apple`，每次按键都是独立的「下一个以此字符开头」。这是 Phase 2，要等维护者定语义。
- **打字时无任何视觉提示**（没有浮动输入框、没有高亮）。
- **自动更新**：若测的是 fork 预发布包，应用内自动更新认不到它（fork 没有签名私钥，资产里没有 `update-manifest*.json`），必须手动装 —— 与本次改动无关。
- **拼音首字母定位**（打 `wd` 找「文档」）不在本期范围，那是搜索侧的能力。
