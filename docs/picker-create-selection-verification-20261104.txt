Open/save picker creation and selection

Cause: the picker used a separate name-entry popup and navigated into a newly
created directory. Its completion handling retained only one destination and
did not explicitly scroll the refreshed selection into view.

Implementation:
- Create folder and text document use shared UniqueChildName and the existing
  operation queue. Name lookup runs off the UI thread, with cancellation checks.
- Shared CreateRenameIntent binds actual completion paths to parent/generation.
  Creation stays in the parent, selects the item, scrolls and starts inline naming.
- Inline editing reuses the shared edit host and renderer RenameFieldRect;
  file stems are selected without extensions, Escape retains created items,
  invalid names remain editable, keyboard commit/cancel returns list focus.
- Copy/move/rename completion selects actual destinations in the current parent.
  Navigation clears pending selection/editor state; stale operation results do
  not modify the newly navigated view.
- Blank-area New text document uses the same creation path.
