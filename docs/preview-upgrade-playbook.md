# Pulse 预览升级实施手册
决策：先用 DOCX 把“选中文件 → 第一屏有效内容”测通，再按瓶颈提速，最后扩格式。不要先换解码库、统一重写所有入口或增加并发。本文是针对当前工作树的实施方案，不是已上线功能或跑分报告。

## 2. 第一个工作包：取得可对照的基线（先不改路由）

在仓库根目录的 x64 VS 开发环境运行以下 PowerShell。创建独立样本目录，任何一步失败即停止；保存输出及目录名。此探针生成旧版 Office 样本，不生成 DOCX。
```powershell
cmake --build build --target pulse_preview_test
if ($LASTEXITCODE) { throw "构建失败：$LASTEXITCODE" }
$d = New-Item -ItemType Directory -Path ("bench_data/preview-upgrade-" + [guid]::NewGuid())
$t = ".\build\pulse_preview_test.exe"
& $t --office-fixtures $d.FullName
if ($LASTEXITCODE) { throw "样本生成失败" }
& $t --office-native (Join-Path $d.FullName sample.doc)
if ($LASTEXITCODE) { throw "原生 Office 协议探针失败" }
```

再制作无隐私 DOCX：第一页有唯一标题、中文和表格，第二页有唯一尾标。记录样本 SHA-256、文件大小、Windows 版本、DPI、实际主程序及宿主路径/哈希、工作树 diff 状态。分别在相同构建的 Quick Look 默认模式与显式系统模式打开；截图核对标题、表格顺序及尾标。若只能在安装版复现，先对齐宿主与资源版本，不混用 build 目录探针的结论。

**诊断交付物**：在样本目录保存 trace、截图、构建身份与结果表。每次选择记录入口、实际 provider、请求/代际、宿主 PID、阶段、原始错误域与错误值；导出用 UTC，耗时用单调时钟。分别打点选择、派发、宿主接收、模型就绪、UI 首次提交有效内容。占位符不算首屏。优先复用 src/common/preview_diagnostics.h；正常日志不要记录正文或完整路径。

| 最后能确认的阶段 | 下一步，只改命中的模块 |
|---|---|
| UI 已派发，宿主未收到 | 核对实际启动路径、退出状态、管道连接及两端版本；区分未启动和断连。 |
| 宿主已收，未交付模型 | 同样本跑宿主探针；分别记录格式识别、解析失败、预算拒绝、用户取消。 |
| 模型正确，窗口空白或显示上一个文件 | 对照 generation、窗口生命周期及首次绘制；不修改 DOCX 解码器。 |
| 仅显式系统模式失败 | 区分 handler 未注册、初始化失败与加载后挂起；保持原生入口可用。 |

## 3. 第二个工作包：缩短首屏，不牺牲切换正确性

1. **排队慢**：先在同入口连续选 A→B→C，记录排队及失效时间。若等待主要来自旧请求，仅合并尚未派发的同窗口旧任务；正在执行的任务沿既有代际取消，交付点再次校验。跨窗口不合并用户意图。
2. **文档解析慢**：仅在 trace 显示模型生成主导时，从 DOCX 做首屏块试点。先交付可独立显示的段落和表格边界，余页按需；区分部分与完整模型。滚动、查找尾标及关闭时取消均要验收。若需要变更 IPC，先实现能力协商；旧端只走完整模型。
3. **大图解码慢**：对比内嵌图命中、低分辨率解码及最终图三条路径。先交付方向正确的低清图，再按实际视口精化；用含 EXIF 旋转、无内嵌图、预算不足三类样本验证。已有快速路径命中且达标就停止，不叠加缓存。
4. **重复打开慢**：先区分宿主启动与重复解码。只有重复解码占主导才试有字节上限的内存缓存；键含文件身份、修改信息、渲染尺寸和 provider 版本。验证同名覆盖、文件变更、不同 DPI 与关闭后回收；身份不可靠时跳过复用。

**建议验收门槛，并非现有成绩**：同机同数据交替运行旧/新构建；每样本各 30 次，分别统计新进程首次打开和同进程重开（前者不等于磁盘冷缓存）。记录首屏 p50/p95、失败数、峰值私有字节和关闭后 5 秒私有字节。目标慢样本 p95 降低至少 20%，对照样本不退化超过 10%；失败不可剔除后宣称达标。连续切换 100 次，旧文档覆盖、主界面失去响应、关闭后仍提交结果均应为 0。若波动接近收益，扩样重测而非宣布提速。

## 4. 第三个工作包：按内容质量扩兼容，不按后缀计数

| 样本 / 环境 | 人眼或自动断言 | 允许的降级 |
|---|---|---|
| DOCX 表格与分页、旧 DOC、伪装成 DOC 的 RTF | 中文、段落顺序、首尾标记；明确是否保留版式 | 原生内容视图标明局限，不把纯文本计为版式成功 |
| 加密 DOC、损坏 PPT、后缀与内容不符 | 加密与损坏区分；无崩溃、无重复拉起 | 给出具体状态和手动打开入口 |
| 大 JPEG、动画 GIF、缺少可选解码组件的媒体 | 方向、首帧、关闭回收；缺组件机器单列 | 静态首帧或元数据，不能记作可播放 |
| 慢 UNC、断连、只读文件；系统 handler 有/无 | 不阻塞 UI，切走后无旧内容；显式系统模式不被悄悄替代 | 有界等待后显示原因，不无限重试 |

先做 DOCX 一行，再按实际失败频率选择下一行。对改动涉及的入口分别覆盖空格预览、悬停及详情；未支持的入口标 N/A 并写明理由。在目标 Windows 10/11 实机核对，若随 Win8.1 包发布则单列该包验证。没机器或没 provider 记“未验证”，不要记通过。新增提示走 tools/l10n/catalog.tsv 并重新生成资源。

## 5. 合并与撤回

按“诊断 → 单一热点优化 → 单一兼容修复”拆分提交。每个提交附样本哈希、入口、前后结果、实际命令与退出码；功能改动另附真实窗口证据。只运行命中模块的定向测试。先让新解码/渐进路径可单独关闭；出现错页、无界内存或旧端不兼容，关闭新路径回到原完整模型，复跑同一失败样本和快速切换。仅当正确性、性能、降级三项证据齐备才扩大默认启用范围。

## 已实施：DOCX 按需读取与真实离屏首绘（后续实测）
原生阅读转换器不再在打开每份 DOCX 时都读 relationships、styles、numbering 三个 XML 部件；在首次遇到关系、段落样式或编号时各读一次，无该特性则跳过。缓存只属于本次转换，不跨文件复用，不扩大原有解码预算。同时保留 Word 不换行连字符 U+2011 与可选连字符 U+00AD，不再替换为普通减号或丢失字符。

旧、新宿主使用相同探针。下表单位毫秒；每个样本/版本 60 次，顺序为旧、新、新、旧，每组 30 次，宿主在组内复用。每次清空视图，从实际 IPC 请求计到 MarkdownView 的 Direct2D EndDraw 返回；包含布局，不包含探针/宿主启动、PNG 编码、显示器呈现。重复使用本地样本，不是冷盘、网络或安装版交互测量。

| 样本 | 旧 p50 → 新 p50 | 旧 p95 → 新 p95 |
|---|---:|---:|
| 普通中文段落 | 4.668 → 0.441 | 6.320 → 4.598 |
| 附带 8000 个未引用样式的合成模板压力样本 | 11.230 → 0.345 | 12.952 → 4.428 |
| 同时使用标题、编号、外链 | 4.487 → 4.228 | 6.809 → 5.533 |

三组普通功能对照的模型字节一致；离屏位图有正文像素，各轮末帧新旧 RGB 逐像素相同。新旧连字符用例有意不同，回滚副本恢复旧模型。另行运行既有 Office 离屏视图套件，详见 office-view.log。未替换安装版，未操作用户桌面。本节证据覆盖原生 Office 阅读路径，不外推为图片、视频、Shell handler 或可见窗口全链路性能。

复测：在 x64 VS 环境构建 pulse_preview_test 和 pulse_office_native_view_test。bench_data/docx-upgrade-ab 下保留同名探针配对的 old/new 目录；在仓库根目录运行 python bench_data/docx-upgrade-ab/ab.py 和 python bench_data/docx-upgrade-ab/draw.py。前者重新生成样本、验证模型并采集独立进程耗时，后者采集离屏首绘并比对像素。结果分别在 ab.json 和 draw.json。

## GIF 动画：减少不透明全宽帧的中间复制
全宽且未声明透明的帧，由 WIC 直接写入已验证的画布行；局部帧和透明帧保留原合成路径。恢复背景按行复制，不改变还原矩形与解码预算。增加了位于画布下方的全宽条带和最后一行的还原/倒序跳帧测试。

后台实机 A/B：同一探针、旧新新旧顺序、每版每样本 80 次 IPC 请求，计到像素返回，不计窗口呈现。1440×900 的四帧 GIF 请求 512 像素时 p50 7.959 → 5.758 ms，p95 9.830 → 8.081 ms；111×75 对照 p50 0.150 → 0.119 ms。四个帧位图逐字节相同，小样本也与独立构造的预期像素一致。测试初次用 256 请求动画时基线返回单帧，这是现有缩略图路由；该次失败不计入动画跑分，另外比对了实际网格缩略图。
GIF 功能 / 内存与还原 / 混合专项分别通过 104 / 6 / 3 项检查。4096 字节局部备份限额通过；没有把省去临时缓冲区等同于实测峰值内存收益，也不把不透明帧的提速推广到所有透明动画。
复测：从仓库根目录运行 python bench_data/gif-direct-ab/check.py。原始耗时 times.json，模块报告 functional.log、memory.log、blend.log。

## BMP 网格缩略图：32 位不透明位图与 52 字节 DIB 头
4:1、8:1、16:1 整数缩图按四个 BGRX 像素一组求和；继续使用原有面积均值和舍入，忽略未定义的 X 字节。52 字节 DIB 头仅在 32 位 BI_BITFIELDS 且 RGB 掩码匹配时走快速路径，其他布局仍走原有回退。生产调用共享此解码器；本轮实测的是文件网格 IPC 请求，不外推为整个文件夹或可见窗口刷新耗时。

实机后台：256 像素网格请求，旧/新/新/旧，3 个性能样本每版各 30 次。旧 → 新 p50（p95），单位毫秒：
- 1024×768：3.155 → 1.892（8.457 → 5.577）。
- 2048×1536：7.776 → 4.625（10.164 → 7.194）。
- 4096×2048：11.458 → 8.580（14.691 → 10.956）。

已用独立整数平均值校验新路径的所有输出像素；另作奇数尺寸、24 位行填充及 32 位透明图像的新旧像素对照，小样本不作性能结论。52 字节头样本旧宿主返回 image-decode-failed，新宿主返回 256×128 位图，独立回滚副本恢复旧错误。非标准通道掩码仍被快速路径拒绝。合成样本，不包含真实设备生成的所有 BMP 变体。
复测：在 bench_data/bmp-box-ab 下运行 python check.py；新旧宿主、探针、各轮数据 times.json 和完整验证记录均在同目录。仅本地构建，未替换安装版。

## ICO、CUR 和动态 WebP：避免读取或复制当前帧不需要的数据
超过 512 KiB 的图标/光标包按目录逐项读取最多 40 字节的格式头，只取选中条目的完整正文；小包仍一次读取。保留 32 MiB 文件上限、256 个条目的原有上限、大小列表顺序和显式选择语义。完整帧可由 WIC 转换器或缩放器直接写入输出，避免应用侧再制作原尺寸中间位图；不缓存用户文件。
